# Windows 앱 이벤트 및 엔진 초안 연동

11/17 백엔드 회신과 11/19 조회한 V3.1 API 명세를 반영한다. 버전 1.0.5에 포함한다.

- 최초 점역 엔진 결과를 편집본과 분리해 보관하고 `pages[].braille[].engineContents`로 저장한다. 기존 서버 점자와 구형 파일의 초기 결과는 추정하지 않는다.
- 로그인·온라인 복귀·전송 전에 `/api/events/config`를 확인한다. 수집이 꺼져 있으면 이벤트를 만들지 않는다. 별도 동의 화면은 추가하지 않는다.
- 열기, 저장, 내보내기, 명시적 완료, 교정 요약, 활동 구간을 `/api/events`에 전송한다. 원문, 점자, 파일 이름, 경로, 예외 메시지는 이벤트에 넣지 않는다.
- `파일 → 작업 완료`는 현재 편집본을 저장한 후 기록한다. 완료 중 사용자 편집을 막고, 백그라운드 점역으로 저장 중 내용이 달라지면 완료하지 않는다. 완료 후 편집하면 새 회차를 만든다.
- 문서 UUID와 회차 번호는 `.smj`에 보관한다. 재열기·프로세스 재시작·계정 또는 수집 컨텍스트 변경 시 새 회차 UUID를 만든다. 편집본 UUID는 내용이 바뀔 때만 갱신한다.
- 작업 생성의 multipart `analyticsContext`, 텍스트 작업 생성·재시도·재개의 JSON `analyticsContext`를 연결한다. 내부 필드는 snake_case다.
- AI 기준본은 새 변환을 직접 요청해서 받은 원문만 보관한다. 저장된 서버 결과를 다시 열었을 때는 초기 AI 원문을 추정하지 않는다. 기준본 버전은 `result.baseline_version_id`, 대상은 블록 `id`다.
- 수동 저장은 첫 전체 요약 이후 변경된 대상만 보낸다. **완료 저장은 전체 요약을 다시 보낸다.** 현재 대시보드가 `job_completed.saved_revision_id`와 같은 요약만 완료 회차로 집계하기 때문이다. 동일 회차·대상·기준본의 최신 요약만 서버 집계에 쓰므로 누적 중복이 아니다.
- 비교는 NFC·Unicode 코드 포인트 Levenshtein이며 동률은 대각선→삭제→삽입으로 선택한다. 400만 셀을 넘는 서로 다른 문자열은 `unsupported`로 명시한다. 추정 거리를 보내지 않는다.
- 활동은 전면 문서의 입력 후 5분까지 active, 이후 idle이다. 30초 구간 보고, 60초 초과 타이머 공백 또는 5초 초과 시계 차이는 unknown이다. 종료 직전에 마지막 구간을 닫는다.
- 대기열은 사용자별 Windows DPAPI로 암호화하고 파일 교체로 원자 저장한다. 프로세스별 파일 임대로 동시 실행 충돌을 막는다. 보존은 30일, 상한은 10,000건 / 암호화 파일 32 MiB다. 상한에서 기존 미확인 이벤트를 지우지 않고 새 수집을 생략한다.
- accepted/duplicate만 확인 후 제거한다. 영구 rejected는 제거하며 CONTEXT_REVOKED는 해당 컨텍스트 전체를 폐기한다. 일시 오류는 원래 ID·순번·본문으로 다시 시도하고, 413은 묶음을 나눈다. 전송 토큰은 로그인 세션에 고정해 다른 계정으로 재전송하지 않는다.

전체·기관 수집 스위치는 서버의 기존 설정을 따른다. 이 변경에서 운영 수집을 켜지 않았다.

검증: 실제 엔진 포함 코어 130/130, Windows 전체 빌드 경고·오류 0, 실제 WPF 이벤트 흐름 및 DPAPI 검사 11개 통과. 전체 WPF 및 배포 패키지 검사는 별도 결과로 기록한다.
